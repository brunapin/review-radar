# ReviewRadar - iOS App Store Review Monitor

ReviewRadar is a full-stack app for monitoring recent iOS App Store reviews.

The backend fetches Apple's customer reviews RSS feed, stores apps/users/reviews, and exposes authenticated API endpoints. The frontend lets users register, log in, add apps, filter reviews, and inspect review metrics from the last 48 hours.

## Requirements

- Go
- Node.js and npm

## Running The Project

Run the backend and frontend in separate terminals.

### Backend

```bash
cd backend
go run .
```

The backend runs on:

```text
http://localhost:8080
```

Optional environment variables:

DATABASE_URL = your Neon connection string (Ex.: postgresql://neondb_owner:**********)
JWT_SECRET = any long random string (Ex.: reviewradar-prod-secret)

Copy in the terminal with your credentials:

```bash
$env:DATABASE_URL="paste_here"
$env:JWT_SECRET="paste_here"
go run .
```

Storage behavior:

- Without `DATABASE_URL`, the backend uses JSON files in `backend/data`.
- With `DATABASE_URL`, the backend uses PostgreSQL through `PGStore`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

The frontend runs on the URL printed by Vite, usually:

```text
http://localhost:5173
```

## Running Tests

### Backend Tests

```bash
cd backend
go test ./...
```

The backend tests cover:

- auth handlers: register/login, password hashing, duplicate email, bad credentials
- RSS feed parsing
- JSON store behavior
- optional PostgreSQL store behavior
- review filtering to the last 48 hours
- newest-first review ordering
- API handler behavior
- CORS for local frontend development

`PGStore` tests are opt-in because they need a real PostgreSQL database:

```bash
cd backend
PGSTORE_TEST_DATABASE_URL=postgres://user:password@localhost:5432/test_db go test ./...
```

On Windows, `go test ./...` can fail with:

```text
An Application Control policy has blocked this file
```

That means Windows blocked the temporary test executable generated by Go. The tests are not necessarily failing. Disable/reconfigure Smart App Control for local Go executables, or run the backend tests in an environment that allows Go test binaries.

### Frontend Tests

```bash
cd frontend
npm install
npm test
```

The frontend tests cover:

- auth provider behavior
- localStorage auth hydration and cleanup
- login page validation and submission
- register page validation and submission
- dashboard rendering, refresh action, empty state, and add-app modal

## API Endpoints

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| `GET` | `/health` | No | Health check |
| `POST` | `/api/auth/register` | No | Create account |
| `POST` | `/api/auth/login` | No | Login and return JWT |
| `GET` | `/api/apps` | Bearer token | List monitored apps |
| `POST` | `/api/apps` | Bearer token | Add app to monitor |
| `DELETE` | `/api/apps/{appStoreId}` | Bearer token | Remove app |
| `GET` | `/api/apps/{appStoreId}/reviews` | Bearer token | Refresh from Apple's RSS feed and list recent 48-hour reviews |

## Backend File Guide

| File | Purpose |
| --- | --- |
| `main.go` | Application entry point. Reads environment variables, chooses JSON or PostgreSQL storage, creates the review fetcher, registers routes, applies middleware, and starts the HTTP server. |
| `models.go` | Shared domain models: `User`, `App`, `Review`, and structs used to decode Apple's RSS feed. |
| `auth.go` | Authentication helpers for hashing passwords with bcrypt, checking passwords, creating JWTs, and validating JWTs. |
| `middleware.go` | HTTP middleware for CORS and Bearer-token authentication. |
| `handlers.go` | HTTP handlers for health, register, login, app management, and review retrieval. |
| `poller.go` | App Store RSS refresh logic. Fetches multiple review feed pages, parses RSS entries, deduplicates results, and stores recent reviews. |
| `store.go` | Store interface plus JSON-file implementation. This is the default local persistence layer. |
| `store_pg.go` | PostgreSQL implementation of the same Store interface. Used only when `DATABASE_URL` is set. |
| `go.mod` | Backend module definition and direct dependency list. |
| `go.sum` | Locked dependency checksums for reproducible Go builds. |
| `assignment_test.go` | End-to-end style backend behavior tests for persistence, recent-review filtering, ordering, required fields, and CORS. |
| `auth_handlers_test.go` | Tests for registration/login handlers, password hashing, duplicate email handling, and invalid credentials. |
| `poller_test.go` | Tests for parsing Apple's RSS feed payload into internal review models. |
| `pg_store_test.go` | Optional PostgreSQL store tests, enabled with `PGSTORE_TEST_DATABASE_URL`. |

`backend/data` is runtime data created by the JSON store. It is intentionally gitignored.

## Library Decisions

### Backend

- Go standard library HTTP server: enough for this API, keeps the backend simple, avoids framework overhead, and makes handlers easy to test with `net/http/httptest`.
- `github.com/golang-jwt/jwt/v5`: JWT support is not part of the Go standard library. This package is widely used, actively maintained, and provides clear signing/validation APIs.
- `golang.org/x/crypto`: bcrypt is not in the Go standard library. This module is maintained by the Go team and is the standard choice for secure password hashing in Go.
- `github.com/jackc/pgx/v5`: native PostgreSQL driver with good performance, context support, pooling support, and strong adoption in Go projects.
- JSON file storage by default: keeps local setup simple for reviewers because the backend works without requiring a database.
- PostgreSQL as optional storage: keeps the app ready for production-style persistence without making local development heavier.

### Frontend

- React: component-based UI model that fits the dashboard, auth pages, modal, cards, filters, and reusable layout pieces.
- TypeScript: catches API/type mismatches early and documents the frontend data contracts.
- Vite: fast local dev server and straightforward production build setup for React.
- `react-router-dom`: handles public/protected routes, login/register navigation, and dashboard routing.
- `date-fns`: lightweight date formatting for review timestamps and relative times.
- `lucide-react`: consistent icon set with tree-shakeable React components.
- Tailwind CSS with `@tailwindcss/vite`: fast utility styling while keeping repeated design values centralized in `tokens.ts`.
- Vitest: test runner that integrates naturally with Vite and TypeScript.
- Testing Library, `user-event`, `jest-dom`, and `jsdom`: test React pages/hooks from the user's perspective with browser-like APIs and readable assertions.

## Assignment Coverage

- Fetches reviews from the App Store customer reviews RSS feed.
- Supports multiple monitored apps.
- Persists users, apps, and reviews.
- Returns reviews from the last 48 hours only.
- Returns reviews newest first.

- Provides JWT-based register/login authentication.
